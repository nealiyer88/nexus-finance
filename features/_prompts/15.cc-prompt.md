Reconciliation logic requirements:
- PSA-side labor total = SUM of `amount` over rows with `category = 'psa'`. Accounting-side invoiced total = SUM of `amount` over rows with `category = 'accounting'` AND `txn_type = 'invoice'`.
- Rows attach to a client either directly via `transactions.canonical_id`, or — for rows whose `canonical_id` is still null — via `(source, counterparty_source_id)` joined to `system_references (source, external_id)`, which joins to `canonical_entities` for tenant scope. This is the same dual join key 12a writes against.
- Money arrives as `amount` already. Do NOT recompute `hours × billing_rate` anywhere in this feature.
- Calculate variance and classify: MATCHED, UNBILLED, OVERBILLED.
- Handle partial coverage: PSA rows exist for a client with no accounting-side counterpart in the same period.

Routes:
- `GET /reconciliation/ar` — per-client: RUDDR labor total, QB invoiced total, variance, status (matched | unbilled | overbilled) for the request's tenant.
- `GET /reconciliation/ar/{canonical_id}` — per-entity detail: line-item breakdown of RUDDR transactions vs QB invoices.

Dashboard page:
- Summary table columns: canonical client name, RUDDR labor $, QB invoiced $, variance $, variance %, status flag.
- Color-coded status: green (matched within tolerance), amber (unbilled beyond tolerance), red (variance beyond the variance-% band).
- Expandable detail: RUDDR rows on the left, QB rows on the right, joined by `canonical_id`.
